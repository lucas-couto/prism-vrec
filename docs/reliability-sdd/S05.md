## Defect and reproduction

ACF declares `requires_components=True`, and `src/steps/train.py` routes embeddings by `is_component_artifact(e) == spec.requires_components`. Only `<extractor>_comp.npy` satisfies that test, and the `fuse` step produced pooled 2-D artifacts exclusively, so no `hybrid_*` artifact could ever reach ACF. The consequence was recorded on 2026-09-08: ACF was dropped from the 3.0.0-rc.1 battery entirely, because a model that only ever sees a native component map cannot answer the dissertation's fusion question.

Confirmed on the current checkout before the change: `_collect_fusion_tasks` reads `<ext>{suffix}.npy` and writes `hybrid_*{suffix}.npy` / `.json`; nothing in the step reads or writes a `_comp` artifact.

## Implementation

Files: `src/steps/fuse.py`, `src/fusions/online.py`, `src/recommenders/base.py`, `src/recommenders/acf.py`.

**Chosen variant — early per-region fusion.** Each source `(n_items, R, D_i)` is flattened to `(n_items * R, D_i)`, the existing pooled strategy runs unchanged on those rows, and the result is folded back to `(n_items, R, D_fused)`. It is the only variant that keeps the `fusion_within_model` axis comparable with the pooled recommenders while preserving ACF's per-region attention: the regions are fused, not pooled away.

- `fuse.py::_fuse_component_rows` — the offline family (`concat`, `pca`, `pca_per_model`). Validates that every source is 3-D and shares the item/region layout, fuses in float32 and casts back to the common source dtype (fp16, the dtype the component grid was sized against). Any fitted parameter is **one basis shared by every region**, because the fit sees the flattened rows. `train_items` is expanded from item indices to the rows those items own (`i * R + r`), so a PCA fit still never sees a validation or test item.
- `fuse.py::_collect_fusion_tasks(component=True)` — reads `<ext>{suffix}_comp.npy`, appends `_comp` last to every output name, and marks offline tasks with `component: True`. The `alignment: pca` route is explicitly **not built** for components and logs a skip rather than emitting a wrong artifact; `alignment: learned` (the configured route) covers the equal-dim family.
- `fuse.py::_fuse_components_enabled` + the second pass in `run()` — the gate and the extra `_collect_fusion_tasks` call per dataset and variant.
- `online.py::load_embedding` — the learned-alignment branch concatenates sources on the LAST axis and reads `source_dims` from the last axis, so a component sidecar yields `RaggedSources` of shape `(n_items, R, sum(D_i))`. The pooled 2-D case is unchanged (last axis is axis 1).
- `base.py::_init_dense_visual` — a 3-D ragged source consumed by a component model keeps its on-disk fp16 instead of being widened to fp32, which would double the catalogue buffer the grid was sized against.
- `acf.py::_project_components` — applies `self._online_fusion` to the raw rows before `W_c` at all three sites (dense gather, lazy gather, catalogue cache). `LearnedAlignmentFusion` is last-axis-wise throughout, so applying it to `(..., R, sum(D_i))` fuses every region independently under ONE shared set of projections. The eval cache key gains `_fusion_parameter_versions()`, because the fusion now sits before `W_c` and an optimiser step on it must invalidate the cache.

Scientific invariants: no loss, candidate set, selection metric or split changed. ACF's score (Eq. 6), attention (Eqs. 8, 10-12) and L2 scope are untouched; what changed is which visual artifact ACF may consume.

## Limits

- **Not resource-certified.** No real-catalogue fusion has been run. The sizing that justified `component_grid: 2` is the researcher's 2026-09-08 estimate: worst cell is ACF x learned fusion on amazon_women (347,591 items, concat 2816-d fp16 per region) at 7.8 GB dense for 2x2, 17.6 GB for 3x3, 31 GB for 4x4. Daytime runs at `vram_share: 0.5` will need the lazy feature residency.
- **`alignment: pca` is not built for components** and is skipped with a log. Only the configured `learned` route and the native-dim family (`concat`, `pca`, `pca_per_model`) produce component artifacts.
- **Declared divergences carried over, not introduced here:** the 7x7 -> 2x2 pooling of the ResNet grid is an overlap-average, while ViT's is an exact partition of its 14x14 map; ACF's history stays bounded at `max_history: 50` against the paper's full `R(u)`.
- **Battery cost.** With 11 fusions plus 8 native component artifacts and the 8-point ACF grid (`lr` x `total_dim` x `att_hidden`), ACF adds 176 jobs per dataset over the native-only 64. ACF time scales linearly with the number of regions.
- No ACF result exists yet under this change: the artifacts must be produced by a `fuse` run and the grid re-run.

## Defect and reproduction

Confirmed on pre-patch `src/steps/train.py` + `main.py` (with E01's `parallel.py` in place), `scratchpad/repro_e02_before.py`: a grid job that raised `RuntimeError("injected failure")` was logged by the worker, `_run_grid` returned normally after "Training complete: 0/1 experiments succeeded.", `main.main([...])` returned `None` without raising and the run manifest recorded `exit_status = ok`. The same control flow existed in `_run_optuna`'s parallel branch (failures logged in a loop, no exception), and `--battery` / `--folds` returned zero regardless of the manifest's `failed` count.

## Implementation

Changed files: `src/steps/train.py`, `main.py`.

`src/steps/train.py`
- `TrainingJobsFailedError(failures, total, *, unit)`: message summarises counts per status, quotes the first 10 failing ids with their error text, and keeps `failures` / `total` / `unit` as attributes.
- `_raise_if_work_failed(results, expected_ids, *, id_key, unit)`: reconciles the collected results against the submitted ids. Non-`ok` -> failed; id with no result -> `unaccounted`; duplicate ids tolerated (first delivery wins). Raises only after logging one line per failure.
- `_run_grid`: after `orchestrator.run(jobs)` and the existing summary line, reconciles against `[job.job_id for job in jobs]`. Completed jobs' checkpoints / grid progress are already on disk; the exception only denies the step its success marker.
- `_run_optuna` (parallel branch): results are now collected in a dict keyed by `cell` (a duplicate delivery no longer ends the loop early); after the join the results are reconciled against every submitted `study_name()` with `unit="cell"`. The sequential branch already propagated the first exception and is unchanged.

`main.py`
- `run_cli(argv) -> int`: calls `main()`; `SystemExit` -> its code, `KeyboardInterrupt` -> 130, any other exception -> logged with traceback, 1. `__main__` now calls `run_cli`, performs the existing thread/child cleanup and ends with `os._exit(code)` instead of the unconditional `os._exit(0)` (previously an exception skipped the cleanup and relied on the interpreter's own non-zero exit).
- `_require_complete(manifest, label)` + `IncompleteRunError`: after `run_battery` / `run_folds`, any cell not in state `done` (`failed`, `pending`, `running`) raises, so `--battery` / `--folds` exit non-zero. The manifest is left as-is for `--retry-failed`.
- `_run_single` was already recording `exit_status="error"` and re-raising; it is unchanged and is what the boundary test observes.

Scientific invariants: none touched.

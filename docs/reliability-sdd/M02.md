## Defect and reproduction

F02: the raw feature matrix is a module buffer, so `model.to(device)` moves the full catalogue and every online-fusion sidecar is stacked/concatenated up front. Reproduced by `test_lazy_model_registers_no_raw_feature_buffer` / `test_buffer_bytes_do_not_grow_with_the_catalogue` (before: the constructor called `np.asarray(source)` on a `FeatureSource`, which is not array-like, and raised / registered a full buffer).

## Implementation

Files: `src/recommenders/base.py`, `src/recommenders/vbpr.py`, `src/recommenders/avbpr.py`, `src/recommenders/deepstyle.py`, `src/recommenders/vnpr.py` (guard + blocked `predict_batch`; caches are M03), `src/recommenders/acf.py` (guards; caches are M03).

- `BaseRecommender.__init__` splits into `_init_dense_visual` (historical path, unchanged behaviour: fp32 upcast, fp16 kept for raw components, `RaggedSources` -> `LearnedAlignmentFusion`) and `_init_lazy_visual` (keeps the source, registers **no** buffer, `visual_features` is the plain attribute `None`, builds the same fusion module from the source's recipe attributes).
- New introspection: `has_visual_features`, `visual_shape`, `is_lazy_visual`; models use these instead of `self.visual_features is None` / `.dim()` / `.shape`.
- `_raw_visual_rows(item_ids)`: dense = buffer indexing; lazy = `torch.unique(..., return_inverse=True)` on the flattened ids, one `read_rows` of the unique ids, transfer to `item_ids.device`, scatter back through the inverse index and reshape to `(*ids.shape, *trailing)`. Repeated ids (ACF padded histories, a positive that recurs in a batch) reproduce the dense rows exactly; dedup is I/O-only. dtype: fp16 kept only for `consumes_raw_components` 3-D sources, fp32 otherwise (mirrors the dense casts).
- `_resolve_visual` now goes through `_raw_visual_rows` and applies the online fusion inside the forward graph — no `detach`; the raw rows are leaves, the projections/gate stay in autograd (verified by identical non-zero fusion gradients).
- `_map_visual(item_ids, fn)`: applies a row-wise `fn(features, ids)` per `_LAZY_ITEM_BLOCK` (8192) rows for lazy sources so a catalogue-sized request (evaluation `predict_batch`) stages at most one block of raw rows on the device; dense path calls `fn` once, unchanged. VBPR/AVBPR/DeepStyle route their projection, attention/style and visual-bias terms through it; VNPR's `predict_batch` under a lazy source fills the `(B, N)` result per item block (`_predict_batch_blocked`), never materialising `(N, dv)`.
- `_visual_generation()`: cache key component (buffer `_version` for dense, source identity for lazy) consumed by M03.

Scientific invariants: none touched — candidate set, masks, loss, regulariser, sampler and effective batch are unchanged; the lazy path is an execution layout (verified numerically).

## Defect and reproduction

Audit F05, re-validated on the current checkout (`src/utils/parallel.py::_WorkerContext.__init__`, `src/steps/train.py::build_job_list/_train_one_optuna_trial`):

- `_WorkerContext.__init__` called `load_config()` in the worker. `set_config_dir` / `set_config_override` are module globals of the parent, so a *spawned* worker re-read `configs/*.yaml` from disk: `--config-dir`, the multi-seed override (`derive_seed_config`) and every CLI override (`--hp-search`, `--n-trials`, `--eval-protocol`) were dropped, and `config["seed"]` / `paths.results` reverted to the YAML defaults for the training call. The in-process (sequential) path only worked because the parent's globals were still set.
- Checkpoint roots: the worker used `CheckpointManager()` (repository default), `build_job_list` and `_train_one_optuna_trial` too, and the grid-progress writer hard-coded `checkpoints/grid_search/`. Under `paths.checkpoints = checkpoints_seed<N>` (multi-seed) or a custom root, the reader (`build_job_list`) and the writer (`_WorkerContext.run`) disagreed, so completed work was never skipped — or was skipped against another run's file.

Pre-patch evidence (scratchpad `repro_e03_before.py`, run on the stashed pre-patch `parallel.py`/`train.py` in the container): `load_config calls in worker: ['load_config']`, `checkpoint root used by worker: checkpoints`, `grid progress under cwd checkpoints/: True`, `grid progress under snapshot root: False`. The new test file fails at collection on the pre-patch tree (`ImportError: cannot import name 'checkpoint_root'`).

## Implementation

Files: `src/utils/identity.py` (new), `src/utils/parallel.py`, `src/steps/train.py`.

- **Resolved snapshot travels with the pool.** `TrainingOrchestrator(config=...)` stores the parent's resolved configuration; `_run_sequential_into` and `_run_parallel` pass it to `_worker_fn(config=...)`, which builds `_WorkerContext(n_workers, wlog, config)`. The worker never calls `load_config()` when a snapshot is present; without one (legacy callers) it logs a warning naming the consequence and reloads from disk. `_run_grid` passes `config`. `_optuna_cell_worker` already received `config` through its process arguments (unchanged).
- **Roots come from the snapshot.** `checkpoint_root(config)` (= `paths.checkpoints`, default `checkpoints`) is used by the worker's `CheckpointManager`, by `build_job_list` and by `_train_one_optuna_trial`; the grid-progress file is `grid_progress_path(manager, key)` = `<manager root>/grid_search/<key>.json`, the same path `load_grid_search_progress` reads.
- **C02 identity module** (`src/utils/identity.py`): `canonical_json` / `canonical_digest` (sorted keys, compact separators, ASCII, finite numbers only; strict type normalisation — bool/int/float kept distinct, NumPy scalars/arrays/tuples converted, `Path` → POSIX string, anything else raises `IdentityError`); `stream_digest` (streamed SHA-256, cached per process by path+size+mtime — mtimes only key the cache, never the identity); `mapping_digest` (by numeric index via S01's canonical order); `split_digest(processed_dir, dataset, splits)`; `feature_recipe` / `feature_digest` (npy: shape, dtype, content digest; sidecar: recipe keys `strategy/online/alignment/dim/normalize/fusion_kwargs` + the recipe of every component recursively, in declared order); `DataIdentity` + `resolve_data_identity(processed_dir, dataset, feature_path, splits=...)` (`SELECTION_SPLITS = (train, val)` for training, `EVALUATION_SPLITS` adds test); `experiment_identity(...)` (schema_version 2: dataset/item-mapping/split/feature digests, `model_name`, `implementation_digest`, `effective_hyperparams`, `selection_budget`, `seed`, `protocol`, `condition`, `fold`; `data=None` records `data_identity: "unresolved"` explicitly); `selection_scope`/`selection_scope_digest` (identity minus hyperparameters — the arena a `_best.pt` competes in); `implementation_digest(model_cls)`; `build_identity_context`; `condition_of`.
- **Jobs carry their data identity.** `build_job_list` resolves `DataIdentity` once per `(dataset, feature)` in the parent and stores its payload in `TrainingJob.data_identity`; unreadable inputs leave it `None` with a warning (the training call then fails on the missing input; nothing is guessed). Consumption of the payload by the training loop is E04.

Scientific invariants: none touched (no change to loss, candidates, tie policy, selection cadence or protocol).

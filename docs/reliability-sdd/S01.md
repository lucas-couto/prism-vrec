## Defect and reproduction

Confirmed in the current checkout (not a hypothesis), via a one-off script in the container:

- `get_item_ids` returned `list(item2idx.keys())`: `{"b": 1, "a": 0}` -> `['b', 'a']`, so the extractor wrote item `b` into row 0.
- `ImageDataset` silently dropped items without an image file (`len == 1`, `valid_items == ['a']` for `["a", "b"]` with `b.png` absent), compacting every later row onto the wrong `item_idx`.
- `validate_features` checked only the row count, so neither defect was detectable after the fact.

Regression file: `tests/test_item_order_alignment.py` (reversed insertion order, random insertion order, hole, duplicate, non-integer index, missing image, end-to-end extract cell with a permuted mapping, sidecar digest verification, same-length reordered catalogue, legacy sidecar without digest, broken mapping at validation time). The end-to-end tests use `_GrayExtractor`, a `BaseExtractor` subclass whose feature is the image's mean gray level (no weights, milliseconds).

## Implementation

Changed files:

- `src/utils/item_order.py` (new private helper): `canonical_item_order` (row `i` = item whose mapped value is `i`; values must be exactly `0..N-1`, holes/duplicates/non-integers raise `ItemOrderError`), `item_order_digest` (SHA-256 over the canonical JSON of the stringified ordered ids), `item_order_metadata` (`{"schema_version": 1, "n_items", "digest"}`), `load_item_order`.
- `src/steps/extract.py`: `get_item_ids` now returns the canonical order (signature unchanged); `ImageDataset` keeps the given order and raises `MissingImageError` naming the missing items instead of filtering (constructor signature and `valid_items`/`valid_paths` attributes unchanged); `_check_extracted_order` asserts the ids the extractor wrote equal the requested ids in order before anything is saved; `_write_meta` receives the `item_order` block for pooled and component artifacts (`_project_pooled` copies the source sidecar, so projected artifacts inherit it).
- `src/steps/validate_features.py`: `_n_items` replaced by the canonical order (a broken mapping is a `FeatureValidationError`); new `verify_item_order` compares the sidecar digest against the current `item2idx.json`; `validate_backbone_feature` / `validate_fused_feature` return `stats["alignment"]` = `"verified"` or `"unverified"` (legacy sidecar without the block: warning + unverified, never relabelled valid; malformed/unknown schema version: error; digest mismatch: error).

Scientific invariants: Q05 enforced; no change to loss, candidates, tie policy, selection or protocol. The fix changes which image lands in which row only for catalogues whose `item2idx.json` insertion order differs from its numeric order or that had missing images. Built-in providers (`write_processed_splits`, DVBPR, synthetic) emit identity mappings in numeric order, so their existing artifacts are byte-identical in content; their sidecars simply lack the digest.

## Implementation

Files: `src/utils/training.py`, `src/utils/checkpoint.py`.

- `_SelectionState` (private) carries `has_valid_observation`, `best_metric`, `best_epoch`,
  `best_ref`, `epochs_without_improvement`, `start_epoch`. `is_new_best`: first finite
  observation wins (even 0.0); afterwards strict `>`. Ties keep the earlier winner and advance
  patience by `eval_every_epochs` (cadence unchanged).
- `_require_selection_metric`: key must exist, be a real scalar (bool rejected, 0-d
  tensors/NumPy scalars accepted via `.item()`), and be finite; otherwise
  `SelectionMetricError`. The exception propagates through the existing `finally`, which
  removes the trial-local file and the resume checkpoint, so no success marker remains.
- After the loop, `not has_valid_observation` raises `SelectionMetricError` (no forced final
  validation; cadence unchanged).
- `_promote_trial_best` validates the trial file through `load_best_checkpoint` (exists,
  deserialises, required keys, finite metric), checks the payload metric equals the observed
  `best_metric` and (keyword-only, optional) the selection fingerprint; missing/corrupt raises
  `BestCheckpointError` instead of a warned no-op.
- Trial-best is written before the resume envelope; the envelope fields for I04 are already
  emitted here (`identity`, `has_valid_observation`, `best_epoch`, `best_ref`, `scaler_state`).

Scientific invariants: loss, optimizer, sampler, full-ranking selection evaluator, cadence,
patience semantics and `_best.pt` comparison rule (`_save_best_model`) untouched.

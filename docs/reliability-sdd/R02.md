## Defect and reproduction

Confirmed on the current checkout:

1. Three producers expanded independently (`_expand_total_dim` in grid / fixed / sampled), and the Optuna fallback sampler recorded single-choice extra keys directly (not through `trial.suggest_*`), so `study.best_params` was a raw suggestion: no per-paper dimensions, no pinned defaults (`l2_reg` when absent from an `hp_space`, single-valued extra keys). The battery replay trained that raw dict (see R01 evidence: `KeyError: 'latent_dim'`).
2. `resolve_cell_hyperparams` (folds) returned the winners-file entry verbatim, so a legacy winner missing a pinned default relied on `train_single_run`'s `hyperparams.get("l2_reg", 0.0001)` fallback instead of an explicit effective configuration.
3. No provenance (raw suggestion, per-key source, study/trial identity) was recorded anywhere.

Before the patch, `tests/test_effective_hyperparams.py` did not import (`EffectiveHyperparamsError` absent); R01's integration test carried the behavioural evidence.

## Implementation

Files: `src/recommenders/hp_search.py`, `src/recommenders/hp_source.py`, `src/battery/execute.py` (replay wiring, see R01).

- `effective_hyperparams(model_name, suggestion, config)`: the ONE canonical path. Fills every declared key (`common:` + the model block's `extra_hyperparam_keys`) that the suggestion lacks and that resolves to exactly one value; a multi-valued key never chosen stays absent (pre-existing behaviour, never fabricated); expands `total_dim` via `resolve_dimensions`; refuses (`EffectiveHyperparamsError`) a direct `latent_dim` / `visual_dim` that contradicts the split. Idempotent, so consumers re-apply it safely. Used by `get_hyperparam_grid`, `get_fixed_hyperparams` and `sample_hyperparams` (initial training) and by `resolve_cell_hyperparams` / `resolve_replay_hyperparams` (winner consumption). The winner export (`export_best.py`, not owned) already writes the effective dict the training received.
- `resolve_replay_hyperparams(config, *, dataset, model_name, embedding_name, search_results_root, search_seed)`: fixed -> pinned; otherwise the primary seed's `_best.pt` is the winner (`load_best_checkpoint`, so a legacy flat state_dict or a missing key raises), its hyperparams re-pass through the canonical expansion; under optuna, `load_existing_study` (never creates; refuses non-persistent storage and absent studies) must hold >= 1 COMPLETE trial and its best trial's expanded `params` must equal the artifact — a disagreement with a different metric raises `WinnerResolutionError`; an exact-metric tie with a different configuration keeps the artifact's configuration (the one the primary seed evaluated) and warns. Provenance records strategy, search seed, artifact path, study/trial numbers and counts, and per-key sources (`suggested` / `default` / `derived`).
- `resolve_cell_hyperparams` (folds) now returns the effective configuration with `suggestion` + `provenance` for both origins.

Behavioural consequence to record: an Optuna trial sampled from an `hp_space` that omits `l2_reg` (or a single-valued extra key) now receives the pinned default explicitly. The value the model sees is unchanged (`train_single_run` defaulted `l2_reg` to 0.0001 anyway), but the `hyperparams` dict — hence `run_id` / job seed / `_best.pt.hyperparams` — differs from a pre-patch Optuna run of the same config. No such run exists (the pipeline restarted from scratch on 2026-09-04 and the frozen battery uses `grid`), so no artifact is invalidated.

Scientific invariants: none touched.

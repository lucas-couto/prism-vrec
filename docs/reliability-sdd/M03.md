## Defect and reproduction

- ACF (`_project_catalogue` + `torch.cat`) built a mandatory `(n_items, M, kv)` fp32 catalogue projection on first eval lookup, unbounded, keyed only by `train()` calls.
- VNPR `_catalogue_visual` cached `self.visual_features[arange]` — a full `(N, dv)` fp32 **copy** of an already-resident buffer.
Reproduced by `test_acf_lazy_mode_holds_no_catalogue_projection_by_default` (before: cache always built), `test_acf_projection_cache_is_invalidated_by_a_parameter_update_without_train` (before: stale `W_c f` served after an in-place weight update without `train()`), `test_vnpr_dense_catalogue_cache_is_a_zero_copy_alias` (before: a separate tensor).

## Implementation

Files: `src/recommenders/acf.py`, `src/recommenders/vnpr.py`.

- ACF `_catalogue_projection()`: optional cache admitted only when `n_items * M * kv * 4 <= limit`; `DERIVED_CACHE_MAX_BYTES = 1 GiB` for dense features (covers every battery catalogue, so historical behaviour is kept), `LAZY_DERIVED_CACHE_MAX_BYTES = 0` for a lazy source (constrained mode: never a derived full-catalogue tensor; M05 may raise it against a measured budget). Key = `(raw-feature generation, comp_projection.weight._version, device)`: an optimiser step bumps the version counter, so the projection is never reused across parameter updates even without `train()`.
- ACF `_projected_components`: training and non-admitted eval project on demand; the lazy source projects the batch's **unique** items in `_LAZY_ITEM_BLOCK` blocks and scatters back (`(B, H)` histories with padded slot 0 and shared items verified against dense rows and gradients).
- VNPR `_catalogue_visual`: the dense full-catalogue "cache" is a zero-copy alias of the buffer (values and order identical); lazy sources use the blocked `predict_batch` (M02) and never cache.

Scientific invariants: none touched.

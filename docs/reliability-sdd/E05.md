## Defect and reproduction

F06 re-validated: `ensure_projected` returned `None` whenever `<extractor>_p<dim>.npy` existed; `fuse.run` filtered pending tasks by `Path(output_path).exists()`, `_fuse_single` returned early on an existing output, and `_ensure_pca_aligned_sources` reused `<ext>_pcaD<dim>.npy` on existence alone. None of them checked the source content, the train-item fit set, the recipe (method / strategy kwargs / normalisation / online alignment), the dimensions or the seed. Pre-patch evidence: the new test file fails at collection on the pre-patch tree (`ArtifactProvenanceError`, `task_provenance` absent) and every "refused" test exercises a code path that used to return `None` / `True` on mere existence.

## Implementation

Files: `src/utils/identity.py` (provenance primitives), `src/extractors/projection.py`, `src/steps/fuse.py`.

- Provenance record: canonical payload of the ingredients + its digest, written atomically to `<artifact>.provenance.json` BEFORE the artifact (a record without its artifact is harmless — recomputed; an artifact without a record can only pass as legacy). `check_provenance` returns `verified` on an equal digest, `legacy` (warning: reused UNVERIFIED, never relabelled) when no record exists, and raises `ArtifactProvenanceError` naming the differing keys otherwise. Nothing is deleted.
- Projection: `projection_provenance` = recursive source recipe (shape, dtype, content digest), method, dim, seed, fit-set digest (PCA variants). `ensure_projected` checks it before reusing an existing output and writes it before filling the output.
- Fusion: `task_provenance` = strategy, normalisation, strategy kwargs, ordered source recipes, fit-set digest (PCA strategies), the online sidecar recipe (minus component names, which the source recipes already pin). `run` attaches it to every task, `_reusable` decides reuse, `_fuse_single` writes it first; `_ensure_pca_aligned_sources` records `{pca_align, source recipe, dim, fit set}` per aligned source and checks it on reuse.
- Path independence: recipes carry file names, shapes, dtypes and content digests but no directories, so identical content under another root is reused (tested).

Scientific invariants: none touched (the fusion arithmetic, PCA fit sets and projections are unchanged; only the reuse decision is).

## Defect and reproduction

F12 re-validated on the current checkout: `write_cell_artifact` wrote `<key>.csv.gz` with `to_csv` and then `<key>.meta.json` with `write_text` — two non-atomic writes with no digest linking them; `read_cell_artifact` / `is_cell_complete` accepted whatever pair existed. A crash between the two left a new records file next to the previous generation's metadata (or a truncated file), and every reader (paired loader, battery idempotency, beyond-accuracy, folds aggregate) accepted it. `evaluate.run` appended per-user rows to the battery CSV (`mode="a"`) and appended done triples, so a re-evaluated cell produced duplicate rows and duplicate completion records. Pre-patch evidence: the new test file fails at collection on the pre-patch tree (`ImportError: STAGE_METADATA`); the four interruption points did not exist as boundaries in the old writer (records write, metadata write, nothing else).

## Implementation

Files: `src/evaluation/persistence.py`, `src/steps/evaluate.py`, `src/battery/manifest.py` (`is_cell_complete`, needed for the reader oracle; the rest of E07 follows).

Publication (`write_cell_artifact`): (0) the expected user population digest is checked against the records before anything is written; a per-cell `.lock` (flock, non-blocking) rejects a concurrent publisher with `ConcurrentPublicationError`; (1) `records.csv.gz` is written and fsynced into a fresh immutable generation directory `<dataset>/.generations/<key>/<utc-stamp>-<uuid>/`; (2) `meta.json` (contract fields + `row_count`, `expected_user_digest`, `completion` block with the SHA-256 of the committed payload) and `manifest.json` are written, fsynced, and the directory is fsynced; (3) the payload is hard-linked into the canonical `<key>.csv.gz` via a temp name + `os.replace` (byte copy through `atomic_write` when links are unavailable); (4) the canonical `<key>.meta.json` — the completion pointer — is replaced the same way. `_stage(name)` marks each boundary for fault injection. Generations are never deleted (`list_generations` enumerates them for explicit cleanup).

Readers: `validate_cell_artifact` requires both canonical files, a readable pointer and, when a completion block exists, `sha256(records) == completion.records_sha256`; a mismatch is a torn pair (`ArtifactIntegrityError`, message names it). `read_cell_artifact` validates first and additionally checks `len(df) == row_count`. A legacy pointer without a completion block is identified with a warning: `read_cell_artifact` still returns it (paired loader / reports keep working on pre-SDD artifacts), `validate_cell_artifact` returns `None`, and `is_cell_complete` treats it as NOT complete (recomputed, never skipped).

Evaluate step: `_evaluate_cell` publishes with `expected_users=evaluator.test_users` and `identity_digest=metadata.config_hash` (the E04 evaluation identity); `_append_cell` now upserts the battery CSV per `(model_name, embedding_name)` and rewrites it atomically (a table without those key columns is still appended, preserving the old contract test); `_record_done` (E04) already rewrites the done table atomically with one row per triple.

Scientific invariants: none touched (records are the same evaluator output; only their persistence changed).

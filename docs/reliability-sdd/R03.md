## Defect and reproduction

F16 re-validated: `resolve_hp_budget` supported `hp_budget[<dataset>]` overrides of epochs / patience / metric / user sample, but the only consumer was `_optimize_one_cell` (for `n_trials`). `train_single_run` read `config["common"]` directly for the other four fields, so an override reached Optuna's trial count and nothing else — the effective budget differed between the resolver and every training path (CLI cell, grid worker, Optuna trial, battery replay, folds). `hp_search._iter_cells_optuna` and the `_run_optuna` log line read `hp_search.optuna.n_trials` directly as well. A requested metric outside the selection evaluator's output (K=10 only) reached the loop and failed only at the first evaluation (I01's `_require_selection_metric`), after the model and data were built.

Evidence before the patch (scratchpad `repro_r01_r03_before.py`): `hp_budget.synthetic.epochs=2` with `common.epochs=6` -> `evaluations=6` at the training boundary (override ignored).

## Implementation

Files: `src/recommenders/hp_budget.py`, `src/utils/training.py` (budget consumption only), `src/recommenders/hp_search.py` (`_iter_cells_optuna` trial count), `src/steps/train.py` (two small hunks: early per-dataset validation in `run()`, per-dataset `n_trials` in `_run_optuna`'s log), `src/battery/execute.py` (budget resolved per cell and recorded in the result).

- `hp_budget`: `SELECTION_K_VALUES = (10,)` is the single declaration of the training-time cut-off; `selection_metric_keys()` derives the accepted `name@K` set from `compute_all_metrics` itself; `validate_selection_metric` refuses anything else; `resolve_hp_budget` casts `n_trials` / `early_stopping_patience` (>= 1), `epochs` (>= 0, an empty schedule is I01's explicit "no observation" failure, not a config error) and `eval_sample_size` (>= 1 or None), then validates the metric.
- `train_single_run`: `budget = resolve_hp_budget(config, dataset_name)` supplies `epochs`, `patience`, `es_metric`, `eval_sample_size`; `batch_size` and `eval_every_epochs` stay in `common:` (not budget fields; cadence preserved); both `Evaluator(k_values=...)` and the selection fingerprint use `list(SELECTION_K_VALUES)`. The selection state, loop, promotion and resume logic are untouched.
- `train.run()` resolves every dataset's budget before any cell trains (fail-fast on an unsupported metric); `_run_optuna` logs the per-dataset trial counts; `hp_search._iter_cells_optuna` takes `n_trials` from the resolver per cell.
- `execute_cell` resolves the budget once per cell and returns it (`result["budget"]`, recorded in the battery manifest).

Scientific invariants: none touched. The selection cut-off remains K=10; no metric definition, cadence or candidate set changed.

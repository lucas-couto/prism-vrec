## Defect and reproduction

Confirmed in the current checkout (`src/evaluation/statistical.py`):

1. `_ensure_config` ran `drop_duplicates(subset=["user_id", "config"])` — a conflicting duplicate (same user/config, different metric) silently kept the first row; an identical duplicate of a *visual* cell (torn append) was also silently accepted.
2. `pairwise_significance` did `pivot[[a, b]].dropna()` — a user missing from one config was inner-joined away; `friedman_test` did `pivot.dropna()` likewise.
3. `per_model_summary` bootstrapped in caller row order, so a reversed frame gave a different CI (found by the order-invariance fixture).
4. No check that a frame mixed seeds / protocols / two artifacts under one config label; non-finite metric values were dropped (`dropna`) instead of failing (Q06).

Evidence: `tests/test_paired_validation.py` — 16 of 21 tests failed before the patch (conflict accepted, missing user inner-joined, order-dependent CI, no provenance checks), all pass after.

## Implementation

Files: `src/evaluation/paired_validation.py` (new primitive), `src/evaluation/statistical.py` (wiring), `src/evaluation/paired_loader.py` (artifact path).

- Observation key = provenance columns (`dataset, seed, split, protocol, eval_protocol_version, fold_policy, split_digest, generation_id` — each single-valued when present) + config identity columns (`visual_input_dim, n_trainable_params, d, checkpoint_digest` — constant within a config) + `(config, user_id)`. `condition` is a source tag, never identity.
- Duplicates: same key + different values -> `ObservationConflictError`; identical rows accepted once only for `embedding_name == "none"` across distinct condition files (or a legacy frame with no `condition` column); identical duplicates of a visual cell or within one condition file -> `DuplicateObservationError`.
- Populations: strict policy raises `UserPopulationMismatchError` listing users absent from each side; `population="declared_intersection"` is opt-in and reports `n_excluded_a/b` (`n_users_excluded` for Friedman). Nothing intersects automatically.
- Non-finite metric -> `InvalidMetricValueError`. Validated frames are sorted by `(config, user_id)` so bootstrap draws are row-order invariant; validation is idempotent.
- `load_paired`: per-cell `validate_cell_records` (unique `user_idx`, finite ranks, manifest `row_count`/`expected_user_digest` when present, legacy metadata accepted explicitly) and cross-cell provenance (`split`, `eval_protocol_version`, `n_items`, metadata dataset vs. directory). Fold policy deliberately not required homogeneous (concatenated K-fold cell pairs with a LOO cell by design; existing test kept).

Scientific invariants: none touched (no loss, candidate set, tie policy, selection or metric definition changed).

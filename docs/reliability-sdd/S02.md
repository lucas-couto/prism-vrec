## Defect and reproduction

Finding F10, re-validated on the current checkout (`src/fusions/online.py::load_embedding`, non-learned branch, and `_load_embedding_lazy` → `StackedFeatureSource`): the equal-dim online sidecar (`adaptive_gated` over PCA-aligned sources, `alignment: pca`, or over projected pre-aligned sources, `alignment: none`) was stacked as stored. The sidecar's `normalize` flag, written by `src/steps/fuse.py` from `normalize_before_fusion`, was read only by the learned-alignment branch.

Pre-patch reproduction (container, CUDA disabled): a sidecar with `normalize: true` over sources `[3,3,3]` and `[1,1,1]` loaded to row norms `[5.196, 1.732]` in both the eager and the lazy path (`sqrt(27)`, `sqrt(3)`); the offline `fuse_mean`/`fuse_sum`/… on the same inputs consume unit rows (`_maybe_normalize`), and `LearnedAlignmentFusion` normalises after its linear map. So the non-learned online representation was the only §10.3 path built from un-normalised sources, and, as documented in protocol §10.3, the higher-norm source dominates every additive fusion. Confirmed behaviour, not hypothesis.

Also confirmed: the legacy test `tests/test_adaptive_gated.py::test_load_embedding_json_sidecar_stacks_components` asserted the buggy behaviour (`normalize: true` with rows equal to the raw inputs); it has been updated to the fixed recipe.

## Implementation

Files: `src/fusions/online.py`, `src/data/feature_source.py`, `src/steps/fuse.py` (outside the listed ownership — three one-line additions, see "Files edited outside ownership").

- `online.py`: `SIDECAR_RECIPE_VERSION = 2` (v1 = implicit legacy: stack as stored; v2: per-source L2 before stacking). The eager non-learned branch applies `l2_normalize` (the offline function: zero rows stay zero, no new epsilon) to every component when `sidecar.get("normalize", True)`, then stacks; the result is a `StackedSources` array carrying the recipe. `normalize: false` returns rows exactly as stored (byte-equal to before). The learned branch is untouched (its module still normalises after `Linear(D_i→D)`).
- `feature_source.py`: `StackedFeatureSource(sources, *, normalize=False, sidecar_recipe_version=None)`; `read_rows` normalises each source's gathered rows with the same `l2_normalize` before stacking, so the lazy rows equal the eager array for every id order and for empty requests. `normalize=True` is refused for non-2-D (component) sources. `recipe_version` property mirrors the eager array.
- `_load_embedding_lazy` passes the sidecar's `normalize` flag and declared version to `StackedFeatureSource`.
- `fuse.py`: the three sidecar payloads (`alignment: none`, `learned`, `pca`) gain `"recipe_version": SIDECAR_RECIPE_VERSION`. `_fuse_single` still skips an existing output, so historical sidecars are never rewritten; loaded through the new code they are reported as `sidecar_recipe_version=None` and built with `recipe_version=2`.

Normalisation point: exactly once, at load, per source, before the online module — the recommender's `_resolve_visual` feeds the slices to `AdaptiveGatedFusion` without any further normalisation (verified by `test_recommender_applies_no_second_normalisation`). No PCA fit changed (`stream_pca_align` / `_ensure_pca_aligned_sources` untouched; the PCA-aligned `.npy` files on disk are the same, only their consumption in the online path changed).

Scientific invariants: Q07 — this is a declared, versioned protocol correction; Q01–Q06 untouched (no loss, candidate set, selection or identity change). Because online `adaptive_gated` cells now consume unit-norm sources, every non-learned online result produced before this change is not comparable with results produced after it (see "Limits").

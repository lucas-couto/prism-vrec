## Implementation

Files: `src/battery/manifest.py`, `src/battery/runner.py`, `src/folds/runner.py`.

- Manifest publication is atomic (`atomic_write`: temp + fsync + rename); an unreadable manifest raises `ManifestError` instead of being guessed.
- `done` semantics: after `execute`, the runner reads the cell's validated artifact (`artifact_binding`) and records it in the entry; an executor that leaves no validated artifact fails the cell. On resume, `done_entry_valid` requires the binding, a validated complete artifact whose payload digest / generation / row count equal the binding, equal provenance, and provenance naming this cell (dataset, visual_config, recommender, seed). A legacy entry without a binding, a missing/torn artifact, a replaced payload or another cell's artifact sends the cell back to `pending` (note recorded) and re-runs it. An artifact that validates and names the cell is adopted as `done` with its binding. `run_battery` logs INCOMPLETE at error level when any cell is not done (main raises `IncompleteRunError`).
- Folds: `fold_plan_digest` = k, partition seed, `min_profile`, the exact user→fold assignment, and the train/val/test split + item-mapping digests; recorded as the cell metadata `config_hash` (flows into partial and concatenated artifacts). `_cell_done` accepts a cell only when the artifact validates (E06), carries concatenated K-fold provenance, `fold.k == folds.k`, `fold.seeds == [seed + i]` and `config_hash == fold_plan_digest`; `run_folds` no longer trusts `state == "done"` alone. Fold trainings pass an identity context with `fold={index, k, partition_seed, min_profile}` so their resume envelopes / winners are bound to the fold (E04); `_load_best_model` uses the validating `load_best_checkpoint` reader. `run_folds` logs INCOMPLETE at error level.

Scientific invariants: none touched.
